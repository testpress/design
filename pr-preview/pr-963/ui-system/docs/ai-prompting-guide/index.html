How to Ask AI to Design Pages

Rule

COMPONENT RULE: Build pages from src/ui-system/components/.

  • If a component exists there, use it.
  • If it doesn't, get the closest one from the Preline MCP, match it to the ui-system styling, and add it to src/ui-system/components/ as a new component.
  • If Preline has nothing suitable either, build it by hand to the ui-system styling.

MULTI-PROJECT & MULTI-BASE RULE: This workspace contains multiple distinct projects (e.g., testpress, flimix, simba, odinhire). Some projects also have separate base templates (e.g., testpress admin base vs student base). Use the product table in CLAUDE.md and the PRD to determine the correct project, folder and base template for your design. If the project, folder, or base template is not explicitly clear from the PRD, you MUST stop and ask the user before generating any UI.

Always reference the UI system docs.

Keep prompts short.

Do not over-explain unless needed.

Standard Prompt

Use this for most pages:

Follow `ui-system/docs`.

Design this page from the provided PRD.

Create in a separate page file.

What NOT To Do

Avoid giant prompts.

Do NOT repeat rules already inside docs.

Bad:

Use components only
Use dark mode
Be responsive
Maintain spacing
Do not invent UI

These should already exist inside ui-system/docs.

If repeated often, the docs are failing.

Goal

Good UI system =

small prompt
consistent UI
reusable components
predictable output
